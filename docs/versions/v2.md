# v2 — Working PR reviewer

## What was built
The scaffold from v1 became a real, working tool: fetch a PR's diff from GitHub, send it to an AI model, print back a review.

- `agents/reviewer/reviewer_agent.py` — `ReviewerAgent.review()` calls Groq (via the OpenAI-compatible SDK) with the diff and returns the model's response.
- `tools/github/github_client.py` — `get_pr_files()` fetches a PR's changed files from the GitHub REST API.
- `apps/cli/main.py` — interactive CLI: asks for owner/repo/PR number, fetches the diff, builds one combined diff string, calls the reviewer, prints the result.

## Key files touched
`agents/reviewer/reviewer_agent.py`, `tools/github/github_client.py`, `apps/cli/main.py`, `pyproject.toml`, `configs/settings.py`.

## Bugs hit and fixed
- Used `OPENAI_API_KEY` as the variable name for a Groq key, and called `model="gpt-5"` — Groq needs its own `base_url` (`https://api.groq.com/openai/v1`) and real Groq model names (e.g. `llama-3.3-70b-versatile`).
- `pip install -e .` failed with "multiple top-level packages discovered" — needed `[tool.setuptools.packages.find]` in `pyproject.toml` to explicitly list which folders are packages.
- Missing dependencies (`requests`, `openai`, `python-dotenv`) weren't declared in `pyproject.toml`, so a fresh install would break even though they worked locally.

## What I learned
- Groq (and similar providers) are "OpenAI-compatible" — same SDK, different `base_url` and model names.
- The difference between the `system` prompt (the AI's instructions) and the `user` prompt (the actual content to act on).
- How to open a real pull request from the command line using `git push` + the GitHub REST API (no `gh` CLI needed).
- Why declared dependencies in `pyproject.toml` matter even when packages are already installed locally.
